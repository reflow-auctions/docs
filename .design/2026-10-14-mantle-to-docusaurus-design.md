# Mantle → Docusaurus migration: design

Status: approved in chat 2026-10-14
Source site: https://reflow.mantledocs.com/
Repo: https://github.com/reflow-auctions/docs (public, branch `main`)
Live URL: https://docs.reflowauctions.com (custom domain on GitHub Pages; served from `/`, not `/docs`)

## Goal

Move every page of the Reflow Auctions help center off HeyMantle into a Docusaurus site we own, deployed to GitHub Pages, editable by non-developers through Pages CMS. Leave Mantle completely (no chat widget, no CDN images).

## Decisions

| Topic | Decision |
|---|---|
| Generator | Docusaurus 3.10.x, classic preset, docs at route base `/` |
| URLs | Doc paths identical to Mantle (`/quick-start/welcome`), `trailingSlash: false` |
| Domain | `docs.reflowauctions.com` from day one; repo stays named `docs` |
| Releases | Docusaurus blog plugin at `/releases`, one file per release: `releases/v1.53.0.md` → `/releases/v1.53.0` |
| Release dates | Copied exactly as on Mantle (incl. v1.15.0/v1.16.0 = 2024, pending owner confirmation) |
| Release headings | Standardized: version = post title; sections = `## Features` / `## Improvements` / `## Fixes` (see mapping) |
| Old release URL | `/resources/release-notes` redirects to `/releases` |
| Search | `@easyops-cn/docusaurus-search-local` (no Algolia approval needed) |
| Editing | Pages CMS (app.pagescms.org), commits straight to `main` |
| Deploy | GitHub Actions → GitHub Pages on every push to `main`; PRs build only |
| Mantle chat widget | Dropped |
| Images | All `cdn.heymantle.com` images downloaded into `static/img/docs/<section>/` |
| Notion links (7) | Kept, and listed in the migration report for owner review |
| Walkthrough videos (3, 66MB on Mantle CDN) | Owner re-uploads to YouTube/Loom; links swapped in via `scripts/migrate/video-links.json`. Originals archived locally in gitignored `.mantle-assets/` |
| Dead links on Mantle (4) | Unlinked (text kept) and listed in the report for the owner |
| Branding | Text logo "Reflow Auctions", accent `#1A1A1A` (from Mantle theme); Mantle has no favicon, so none |

## Content conversion ("simple" mode)

Mantle pages use custom elements. They become plain Markdown that the Pages CMS rich-text editor can safely round-trip:

| Mantle | Markdown |
|---|---|
| `<m-tip>` `<m-note>` `<m-info>` `<m-warning>` `<m-danger>` | `:::tip` / `:::note` / `:::info` / `:::warning` / `:::danger` admonitions, blank lines around directives |
| `<m-steps>` + `<m-step title>` | Ordered list; each item starts with the bold step title |
| `<m-accordiongroup>` + `<m-accordion title>` | `### title` followed by its content |
| `<m-cardgroup>` + `<m-card title href>` | Bullet list; bold title (linked when `href` present) then its text |
| `<m-frame>` | Unwrapped (image only) |
| Empty `<p></p>` | Removed |
| Links to `reflow.mantledocs.com/...` | Site-relative `/...`; `/resources/release-notes` → `/releases` |

Files use `.md` (CommonMark), not MDX, so curly braces like `{{idsForeachitem}}` and stray `<` don't break the build.

### Release section label mapping

Labels found on the Mantle page. They appear as `<h3>`, bold-only `<p>`, plain `<p>`, or `<div>`-wrapped text; matching ignores case, a trailing colon, and dash style:

| Mantle label | New heading |
|---|---|
| Features | `## Features` |
| Main improvements, Improvements | `## Improvements` |
| Main improvements — Admin App | `## Improvements (Admin app)` |
| Other fixes/improvements, Fixes/improvements, Main fixes and improvements, Other fixes | `## Fixes` |
| User Side – Main fixes/improvements | `## Fixes (User side)` |
| Admin App – Main fixes/improvements | `## Fixes (Admin app)` |
| Note, Resolved | Left as bold paragraphs (they're content, not labels; v1.37.0's "**Resolved** / minor bugs…" is one broken sentence, listed in the report for a human fix) |

Any label not in this table stops the migration with an error, so nothing is silently mangled.

## Repository layout

```
docs/<section>/<page>.md      33 pages, front matter: title, sidebar_position, optional sidebar_label
docs/<section>/_category_.json  {label, position} from Mantle nav order
releases/v<x.y.z>.md          42 posts, front matter: title (= version), date (YYYY-MM-DD)
static/img/docs/<section>/    downloaded screenshots
src/pages/index.js            redirects / → /quick-start/welcome (Mantle does the same)
src/css/custom.css
docusaurus.config.js, sidebars.js (autogenerated from folders)
scripts/check-content.mjs     CI guard: no Mantle references; release file name == title; valid date
.pages.yml                    Pages CMS config
.github/workflows/deploy.yml
.design/                      this spec + implementation plan (not published)
```

`scripts/migrate/` exists only during migration and is deleted afterwards.

## Build guarantees

The build fails (and the live site stays as it was) when:
- any internal link, anchor, Markdown link, or image is broken (`throw` on all four)
- any file under `docs/`, `releases/`, `src/`, `static/` (text files), or the site config mentions `heymantle.com` / `mantledocs.com`
- a release file name doesn't equal `<title>.md`, the title isn't `vX.Y.Z`, or the date isn't `YYYY-MM-DD`

## Pages CMS

- Collections: **Docs** (`docs/`, tree view, subfolders) and **Releases** (`releases/`, sorted by date desc).
- Release filename template `{primary}.md`, with the filename shown on create. Pages CMS slugifies field tokens, which could turn `v1.54.0` into something else. The editor confirms the filename, and the CI check rejects a mismatch.
- Media: uploads go to `static/img/docs`, and are written into content as `/img/docs/...`.
- `settings.content.merge: true` so keys the CMS form doesn't know about (e.g. `sidebar_label`) survive edits.
- Editors need a GitHub account with write access (or a Pages CMS email collaborator invite).

## Owner actions (can't be automated from here)

1. DNS: `CNAME docs → reflow-auctions.github.io`.
2. Repo Settings → Pages → Source: GitHub Actions; Custom domain `docs.reflowauctions.com`; Enforce HTTPS.
3. Recommended: verify `reflowauctions.com` in org Settings → Pages (prevents domain takeover).
4. Install Pages CMS GitHub App on `reflow-auctions/docs`; grant editors access.
5. Before cancelling Mantle: ask them to redirect `reflow.mantledocs.com/*` → `docs.reflowauctions.com/*` (paths match), and update links in the Shopify listing, the app, and emails.
6. Confirm the v1.15.0 / v1.16.0 years.

## Acceptance

- 33 doc pages + 42 release posts build and deploy; sidebar order and labels match Mantle.
- Zero Mantle references in published content; all 60 images served from our domain; the 3 videos point to their new host.
- RSS (`/releases/rss.xml`) and Atom feeds exist.
- `/releases/v1.53.0` loads on the live site (if GitHub Pages mishandles the dotted path, stop and ask the owner before switching to `v1-53-0`).
- `/resources/release-notes` redirects to `/releases`.
- A Pages CMS test edit (text + image + admonition) round-trips without breaking the Markdown and deploys automatically.

## Out of scope

Algolia DocSearch, versioned docs, i18n, analytics, a support chat replacement, editing approvals/branch workflow.
